## Dated S5C decisions — 10–11 September 2026

1. S5C is the mandatory "S5B Projects + Project Media administration" slice named as a requirement in the S9A-P and S6A decisions above — it is not new scope, it is the deferred work finally being done.
2. Public project narrative reuses the existing four fixed `project_localizations` fields (challenge/approach/solution/outcomes, plus `project_scope` as "Scope") as the authoritative public chapters, and the existing `project_stages` table as bounded, optional editorial "story chapters" with per-chapter media — no new flexible content column was added; see `docs/CLAUDE_C3_PROJECT_CASE_STUDY_ARCHITECTURE.md` for the full tradeoff.
3. `RealProjectCaseStudy` (`src/components/site/real-project-case-study.tsx`) is the one component rendering real project data, used identically by the admin private draft preview and the real public `/projects/[slug]` page. The six C2 concept studies keep their own, deliberately separate preview rendering system; the two were never meant to share a renderer.
4. A pre-existing S4 kernel gap — `register_media_asset` left assets in `registered` state and nothing ever moved them to `ready_private`, so `promote_media_asset` could never accept a real upload — was fixed with one new forward-migrated function, `finalize_media_upload`. This was already broken before C3; it blocked the Media Command Center from working for real (non-fixture) media, so it was fixed rather than deferred.
5. `admin_clear_and_promote_project_media` is a bounded convenience wrapper over the existing `update_media_rights`/`promote_media_asset`/`promote_project_media` kernel calls, not a new business rule; concept/generated/synthetic provenance is still rejected at the database level regardless of which path is used.
6. The Services public-content dual-source problem (C1's static `SERVICE_CATEGORIES` taxonomy competing with the Admin-managed `services` table) is fixed with one adapter, `src/features/services/service-source.ts`, now the sole source for `/services`, `/services/[slug]`, the home page, the header mega-nav panel, and the footer. The equivalent Projects three-state rule (concept studies fall back only while nothing real is published; preview off never shows a concept study) was already correctly implemented inline in the two Projects public routes and was left there rather than extracted into a third adapter file, since there are only two consumers; see the architecture doc for the exact reasoning.
7. Reordering project media uses keyboard-accessible Move Up/Down controls, not a drag-and-drop library.
8. Removing a project's media usage deletes only the `project_media` junction row; the underlying `media_assets` row is never hard-deleted by that action.
9. Given the time budget, the required synthetic end-to-end workflow proof was written as a bounded Node script exercising the real RPC/Storage layer directly (`scripts/verify-s5c.mjs`) rather than a full 25-step Playwright browser suite; the Admin UI itself was exercised manually/visually, not through a new automated browser suite, in this slice.
10. No C4 (Clients/CRM, operational project, invoice, contractor, payment, or private-ops analytics) table, route, or column was created. `public.projects`/`public.project_localizations` remain the public case-study domain only; see `docs/CLAUDE_C3_PUBLIC_OPERATIONAL_PROJECT_BOUNDARY.md`.

## Dated S4 decisions — 5 September 2026

1. S4 may implement the content/evidence/media/publication kernel without waiting for real client facts. It must fail closed when facts, rights, consent, review, or ownership are missing.
2. Content lifecycle remains `draft|published|archived`; evidence state remains independent (`unverified|in_review|verified|expired|rejected`). No speculative scheduling or approval state was introduced.
3. Evidence relationships are typed foreign-key tables. A generic `entity_type/entity_id` claim/evidence escape hatch is not accepted.
4. Concept, generated-reference, and synthetic media are never promotable to completed-project public evidence. Unknown/expired/rejected rights are not public-eligible.
5. The local Storage API is enabled only for two private buckets; migrations do not mutate provider-managed Storage metadata. Provisioning and reconciliation use supported APIs.
6. Public projection views use explicit columns with owner-evaluated `security_invoker=false` and `security_barrier=true`; anonymous access is projection-only and all editorial/evidence/claim/registry/settings/media base-table `SELECT` grants are revoked.
7. S4 does not begin S5 UI, S6 public routes, public intake, production uploads, cloud resources, deployment, orders, invoices, analytics, or real content promotion.
8. Page-section registry scope is enforced independently from the parent page template by the forward senior-review migration `20260905160000`; homepage-only and page-only section types cannot cross scopes.
9. Optional public canonical overrides are constrained to trimmed absolute HTTPS URLs by `20260905161000`; null remains the safe default.
10. UUID-rooted object paths and the admitted MIME/media-kind contract apply to every provenance class, including synthetic fixtures; `synthetic_test` only prevents public promotion and is not a metadata-validation bypass.

## Dated S4 senior-review decisions — 6 September 2026

1. The data-only public-content contract applies to every projected text field, not only body blocks. PostgreSQL and TypeScript admit only the exact heading/paragraph/list/link block shapes and reject raw markup or executable-protocol text at publication/effective-read boundaries.
2. Public page paths, content links, navigation targets, canonical overrides, and allow-listed URL settings fail closed on private namespaces, backslashes, control characters, and other ambiguous forms appropriate to each field.
3. Eligible project-media metadata is not independently public: its boolean RLS predicate now also requires a currently publishable parent project plus safe English usage metadata.
4. Storage reconciliation paginates deterministically and fails closed beyond its explicit 10,000-entry local-run bound; it never silently truncates or repairs uncertain state.
