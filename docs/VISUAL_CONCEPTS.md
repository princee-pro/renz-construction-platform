## 1. Generation method

- **Mode:** built-in OpenAI Image Gen, UI-mockup mode for interface boards and logo/brand mode for identity boards.
- **Input evidence:** the supplied written brief plus the provisional Datum & Mass system in `DESIGN.md`.
- **Missing source caveat:** no client brand board, original logo, or WhatsApp services image was available. The visual direction cannot be compared with or approved against the existing identity.
- **Production boundary:** concepts are composition and art-direction references. Phase 1 must implement semantic, responsive components and use licensed/verified media; it must not slice, trace, or present a screenshot as an interactive page.

## 2. Shared art-direction prompt

All UI boards used this normalized base prompt:

> Create a high-fidelity editorial interface concept for RENZ Construction Services Ltd in a distinctive “Datum & Mass” direction: deep structural navy `#071523`, restrained gold `#C69A3A`, true white, cool concrete `#F1F2EF`, graphite text, Montserrat-like geometric display typography, highly readable humanist body type, square architectural geometry, one continuous gold survey datum, generous negative space, strong photographic crops, plan/section annotations, and premium but usable hierarchy. Avoid generic construction templates, card grids, glassmorphism, gradients, glow, cream/brown lifestyle styling, crane/roof clip art, pill-heavy UI, and tiny illegible text. Treat all building imagery and project details as clearly non-client concept material.

Each board then added the exact screen/chapter content below. Image generation can render imperfect text and controls; copy in the boards is illustrative and never the content source.

## 4. Logo exploration prompt set

### Round 1 — divergent structures

[09 Logo Exploration](../design/concepts/09-logo-exploration.png), 1536×1024, used this normalized prompt:

> Explore multiple flat, vector-like RENZ identity directions derived from architecture, surveying, structural planes, and the letter R. Use deep navy, restrained gold, and white. Show symbol, wordmark relationship, one-color/small-size considerations, and concise rationale. Avoid roofs, cranes, buildings-in-a-badge, gradients, bevels, glow, metallic effects, generic monograms, and declaring any option final. Mark the board provisional because the original client logo is missing.

Review result: the board established useful column, fold, and datum ingredients, but its glow/presentation polish and several options were too generic to approve. It was treated as a divergence exercise, not a selection sheet.

### Round 2 — Structural Fold R refinement

[10 Structural Fold R Refinement](../design/concepts/10-logo-structural-fold-refinement.png), 1536×1024, used this normalized prompt:

> Refine one flat “Structural Fold R” concept: an unmistakable R assembled from a vertical column, a roof/fold plane, a precise diagonal leg, and one gold survey datum. Present primary horizontal lockup, symbol, reverse, one-color, small-size, and simple construction logic. Use no gradients, shadows, glow, bevels, mockups, crane/roof clip art, or fake trademark claims. Label it PROVISIONAL and state that the original client mark is required before approval.

Review result: this is the clearest provisional direction because the R remains legible, the datum integrates with the wider UI system, and the construction is more ownable than generic roofline marks. It is still not final and requires vector reconstruction, optical correction, small-size tests, source comparison, legal/distinctiveness review, and written approval.

## 5. Visual review ledger

All ten concept files were opened and inspected at high detail after generation.

| Review area | Finding | Disposition |
|---|---|---|
| Cross-screen coherence | Navy, gold datum, square geometry, editorial type, and concrete surfaces form one family across public, wizard, and admin boards. | Carry the grammar into tokens/components; keep public/admin density distinct. |
| Homepage rhythm | The five homepage boards create varied chapters rather than repeating one split layout or card grid. | Preserve sequence and contrast; do not concatenate PNGs into a fake full page. |
| Legibility | Generated copy has the usual image-model imperfections and some small annotations are not production-readable. | Re-author all UI in semantic HTML with real copy and responsive type. |
| Evidence integrity | Building images, facts, dashboard names/counts, and diagrams are synthetic concept material. | Never publish as RENZ work, structured data, testimonial, metric, or operational seed. |
| Expertise model | Three service families simplify a ten-service list and create a strong navigation/explorer structure. | Validate regulated terminology and actual delivery scope with the client. |
| Wizard | Ten-stage anatomy communicates completeness but could feel heavy if implemented literally. | Use the seven-step recommendation in `PROJECT_BLUEPRINT.md` and `CONTENT_MODEL.md`. |
| Admin | The restrained product register avoids a marketing-site dashboard while sharing the brand datum. | Build familiar table/form/feedback behavior from `UX-CONTRACT.md`; treat board values as placeholders. |
| Motion potential | Hero, projects, and process boards provide clear line/plane transition opportunities. | Admit only under `MOTION_SYSTEM.md`; mobile/reduced-motion use static normal flow. |

| Logo round 2 | Structural Fold R is more coherent and reproducible, but untested against the real identity and market. | Provisional reference only; blocked by source recovery and approval. |

## 6. Asset handling and ethics

- Keep these files under `design/concepts/`; do not upload them to production CMS buckets.
- Any internal presentation must label them “AI-generated concept—not RENZ project photography.”
- Do not crop away the provisional/concept context where that could imply completed client work.
- Do not use generated people, logos, credentials, seals, site signage, map locations, or dashboard details as evidence.
- Replace concept buildings with client-approved photography and drawings whose ownership and permissions are recorded.
- Preserve prompt/date/model-mode metadata in this manifest; future regenerations create new files or a revision log rather than silently overwriting the approved review set.
